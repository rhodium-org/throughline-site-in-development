# throughline-site-in-development

The quality bar for a site that is **reachable by the public while it is still being
built** — a composable [throughline](https://github.com/rhodium-org/throughline) source
for any project that publishes before it is finished.

A site under active development is judged by what it serves today, not by the plan.
Every published address is a promise. This graph says what keeping that promise means
in practice: when a link may be published, what a holding page must and must not do,
how interim content ships, and how the site proves from outside that it is telling
the truth.

## Using it

Declare it as a source and cite its items with `satisfies` links:

```toml
[[sources]]
namespace = "site"
url = "https://github.com/rhodium-org/throughline-site-in-development"
ref = "v0.1.0"
```

```yaml
links:
- target: site:REQ-0003
  type: satisfies
```

Verification lives in the consuming site, not here: the checks a site runs against its
own public addresses are what prove these requirements hold. That is why this graph
carries no `test` items and no coverage rule.

A commit in a consuming repository cites an item here by naming both the graph and the
UID — `throughline-site-in-development REQ-0003` — because UIDs collide across graphs.

## Status

Items authored with AI assistance carry `origin: ai` or `origin: hybrid` and are born
`proposed`. The graph's own gate refuses to let such an item count as agreed until a
human has ratified it, so `tl check --strict` stays red until then. That is the gate
working, not a defect.

## Layout

```
vision/        INT-0001    why a site in development is judged by what it serves
risks/         RISK-0001…  what goes wrong when it is not
requirements/  REQ-0001…   the quality bar
non-goals/     NG-0001…    what this source deliberately does not cover
docs/spec.md               generated by `tl docs`, gated by `tl docs --check`
```
